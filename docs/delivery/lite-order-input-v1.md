# Lite 下单输入语义（Order input semantics）— 交付说明 v1

> 这份文档说的是 Lite 合约下单面板（生产页 `/trade`）里那个「How much」金额输入框到底代表什么钱。结论：**输入的是用户自己掏的钱**，Boost 只放大仓位，不改变输入框的含义。写给第一次接手这块的研发 / 测试 / 真平台对接方看，不需要任何前置背景。读法：先看 §0，再按 §1 的算例把数字对一遍，然后用 §3 做迁移对照。

## 1. 定稿语义

Lite 下单输入框里的数字 = 用户这一单掏出去的钱。

| 量 | 公式 |
|---|---|
| 输入 | 用户键入金额（下称 `A`） |
| 仓位规模 notional | `A × Boost` |
| 份数 qty | `A × Boost ÷ 价格` |
| 手续费 fee | `A × Boost × 0.001` |
| 最多亏 Max loss | `A`（恒等于输入，切 Boost 不变） |
| 赢了拿回 win | `(1 − 价格) × qty` |
| 派生行 | `= {A × Boost} position`，仅 `Boost > 1 且 A > 0` 时渲染 |

Pro 侧输入语义是交易所惯例的 notional / 数量，两面各自 canonical，不互相迁移。

### 全量算例：输入 10 · Boost 3× · 价格 94¢

账户可用余额按 $40 计（auto-close 依赖账户快照，其余各项与余额无关）。

| 字段 | 数值 | 算法 |
|---|---|---|
| 仓位规模 | `$30.00` | 10 × 3 |
| 手续费 | `$0.03` | 30 × 0.001 |
| 实际扣款 | `≈ $10.03` | 输入 + fee |
| 份数 qty | `31.9149` | 30 ÷ 0.94 |
| 赢了拿回 win | `$1.91` | (1 − 0.94) × 31.9149 |
| 最多亏 Max loss | `$10.00` | = 输入 |
| Est. auto-close | `≈ 31¢` | 0.94 + (10 − (40 − 10 − 0.03)) ÷ 31.9149 |
| 输入框派生行 | `= $30.00 position` | money(10 × 3) |

同一笔在 1× 下：仓位 $10、fee $0.01、qty 10.6383、win $0.64、Max loss $10、auto-close `None`、派生行不渲染。

## 2. 面板逐字段响应表

| 字段 | 改输入时 | 切 Boost 时 |
|---|---|---|
| Max loss · what you pay | 跟随输入 | **不动**，恒 = 输入 |
| 赢了拿回 win | 线性跟随输入 | 线性放大（3× = 1× 的三倍） |
| Est. auto-close | 重算 | 重算；1× 恒为 `None` |
| 输入框派生行 | 重算，`A = 0` 时消失 | 重算，切回 1× 时消失 |
| Max 按钮 | — | 填入可用余额，**不乘 Boost** |
| $10 / $25 / $50 / $100 预设 | 直接写入输入框 | 预设是 margin 值，不随 Boost 缩放 |
| CTA 金额 | 跟随 win | 跟随 win |

## 3. 真平台对齐表（从 notional 语义迁移）

| 维度 | notional 输入语义（真平台现状） | Lite margin 输入语义（本规格） |
|---|---|---|
| 输入含义 | 仓位面值 | 用户掏的钱 |
| qty | `输入 ÷ 价格` | `输入 × Boost ÷ 价格` |
| win | `(1 − 价格) × 输入 ÷ 价格` | `(1 − 价格) × 输入 × Boost ÷ 价格` |
| Max loss | 随杠杆变化 | 恒 = 输入 |
| fee | `输入 × 费率` | `输入 × Boost × 费率` |
| auto-close | 按 notional 求解 | 同一求解器，quantity 取放大后的 qty |
| Max 按钮 | 常见为余额 × 杠杆 | 余额本身，不乘 Boost |
| 金额预设 | notional 档 | margin 档 |
| Pro 端 | — | 零改动，继续用 notional / 数量输入 |

## 4. 实现核对三件事

1. **fee 按 notional 计**：`fee = 输入 × Boost × 费率`，随 Boost 增大；余额预检查按 `输入 + fee`，不是按 notional。
2. **面额记账口径**：仓位券 / 体验仓的面额统一按 margin 记账（即券面值直接进输入框，不乘 Boost）。真平台侧现状请对照自查后回话。
3. **1× 回归锚点**：Boost 为 1× 时两套语义的每一项数字必须逐项相等（notional、qty、win、fee、Max loss）。迁移验证从这一档开始。

## 5. 验收清单

- 输入 10 + Boost 3×：扣款 ≈ $10 + fee、仓位 $30、win 为 1× 档的 3 倍、Est. auto-close 给出具体价位。
- Boost 由 1× 切到 5×：Max loss 数字不动；win 与 Est. auto-close 同步变化。
- 派生行三状态：1× 或空输入 → 不渲染任何 DOM；`Boost > 1 且输入 > 0` → 显示 `= {金额} position`；改输入或切 Boost → 金额即时重算。
- 桌面卡与移动 drawer 表现一致（框架不同，内容同一份组件）。
