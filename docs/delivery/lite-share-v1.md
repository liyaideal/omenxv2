## §1 功能目标

让已登录用户把自己的一笔仓位或一次结算，一键做成一张带品牌与邀请码的图片，保存或分享到社交渠道。目的是拉新：每张图都带邀请码和二维码。

关键约束三条：

1. **只对已登录用户开放**。未登录时分享入口不渲染（不是禁用、是不存在）。
2. **海报是图片，不是网页**。它在浏览器里现场渲染成 PNG，所以海报内所有样式必须是内联样式、且不依赖网络字体（见 §6）。
3. **一张海报只讲一笔**。不做多仓合并、不做历史汇总。

## §2 三种海报形态

海报有三个形态，由仓位当时的处境决定。形态决定四处显示：

| 形态 | 什么时候 | 右上角标签 | 盈亏区标题 | 右侧金额格标题 |
|---|---|---|---|---|
| 进行中 | 仓位还开着，价格还在动 | `LIVE CALL` | 盈：`Profit so far` ／ 亏：`Lost` | `Now worth` |
| 已平仓 | 用户主动平仓离场 | 平仓日期，如 `AUG 28, 2026` | 盈：`Profit` ／ 亏：`Lost` | `Cashed out` |
| 已结算 | 事件出结果、系统结算 | 结算日期 | 盈：`Profit` ／ 亏：`Lost` | `Paid out` |

盈亏方向（盈 / 亏）由金额正负决定，与形态无关。盈亏方向决定整张海报的配色与插画：

| | 盈 | 亏 |
|---|---|---|
| 强调色 | volt `#CFFF4A` | 红 `#EF4444` |
| 头像环 / 角标 | 绿环 `rgba(34,197,94,0.4)` ＋ volt 角标 | 红环 `rgba(239,68,68,0.4)` ＋ 红角标 |
| 状态药丸 | volt→蓝渐变 | 红→橙渐变 |
| 背景插画 | 山猫举望远镜坐酒桶 | 山猫仰面躺倒 |

## §3 数据库

**分享功能自己不写任何数据**，没有 share 表、没有埋点写入。它只读三处：

| 读什么 | 从哪 | 用在哪 |
|---|---|---|
| 用户名、头像地址 | 用户档案 | 海报左上角 |
| 邀请码 | 邀请码表（按用户查，查不到会自动生成一个 6 位码） | 海报页脚文字 + 二维码 |
| 仓位/结算的金额、事件名、方向、时间 | 调起分享的那个页面已有的数据，直接透传 | 海报正文 |

研发注意：邀请码是**异步查出来的**，海报出图不能早于它返回，否则会印出占位码（见 §8 第 1 条）。

## §4 用户端流程

### 4.1 入口

分享入口一共七处，全部只在已登录时渲染：

| 入口 | 在哪 | 控件 |
|---|---|---|
| 合约持仓卡 | 交易页进行中的仓位 | 卡片右上角 28px 分享图标 |
| 合约多腿持仓卡 | 交易页同一事件多个方向的仓位 | 同上 |
| 合约结算卡 | 交易页事件已出结果后的结果卡 | 文字按钮「Share」 |
| 现货持仓卡 | 现货交易页的仓位 | 分享图标 |
| 组合列表 | 组合页进行中的持仓（卡片视图与列表行视图各一处） | 分享图标；列表处于多选模式时不渲染 |
| 结算详情 | 单笔结算详情页 | 页头分享图标 |
| 平仓后自动弹出 | 用户平仓成功之后 | 无需点击，自动带着这笔的快照弹出 |

### 4.2 弹窗

点开后是一个居中弹窗，从上到下：标题、副标题、海报预览、四个方块按钮、一个主按钮。

标题与副标题跟着盈亏走：

| | 标题 | 副标题 |
|---|---|---|
| 盈 | `Share Your Win 🏆` | `Show off your trading success` |
| 亏 | `Share Your Trade` | `We go again next time!` |

五个动作：

| 动作 | 做什么 | 备注 |
|---|---|---|
| Save | 把海报下载成 PNG 到本地 | 图还没生成完时按钮置灰 |
| Copy Link | 复制分享链接到剪贴板 | 复制后按钮文字变 `Copied` 两秒 |
| X | 新窗口打开 X 的发推页，预填文案与链接 | |
| Telegram | 新窗口打开 Telegram 的分享页，预填链接与文案 | |
| More Options | 调起系统原生分享面板，条件允许时连图片一起分享 | **仅在浏览器支持原生分享时才渲染**，桌面浏览器大多看不到这个按钮，属正常 |

分享文案统一是：`I just won {百分比}% on OMENX! 🚀`（亏时为 `I just lost {百分比}% on OMENX! 💀`），百分比带正负号、保留一位小数。

### 4.3 海报内容

从上到下：

1. 头像（52px 圆形，带光晕环，右下角一枚 20px 圆形角标：盈为奖杯、亏为下跌箭头）
2. 用户名 + 状态药丸（盈进行中 `⚡ Winning!`／盈已了结 `⚡ Winner!`／亏 `💀 RIP`）
3. 右上角形态标签（见 §2）
4. 盈亏区：小标题 → 大金额 → 收益率 + `ROI` → 一句调侃
5. 一条分隔线，然后事件名（最多两行）+ 方向行
6. 两个金额格：左「Put in」放本金，右按形态显示当前价值 / 平仓所得 / 结算所得
7. 页脚：邀请码 → OMENX 字标 → 号召语 → 右侧二维码 + `omenx.com` 字样

那句调侃按收益率自动选，规则如下（研发按这个实现，不要照设计稿里的示例文字）：

| 条件 | 文字 |
|---|---|
| 收益率 ≥ 100% | `🔥 Absolute legend!` |
| 收益率 ≥ 50% | `💰 Nice gains!` |
| 其余盈利 | `✨ Well played!` |
| 亏损 ≤ −50% | `😭 That's rough buddy...` |
| 其余亏损 | `📉 We go again!` |

号召语：盈 `Join & trade like a pro!`，亏 `Join & do better than me 😅`。

## §5 字段与文案

所有用户可见词条已进 `docs/copy-dictionary.md` 的「Share / 晒单（Lite）」节，包含标准写法、含义与禁用变体。本文不复制，避免两处漂移。

金额与百分比口径：金额一律两位小数、带货币符号；百分比一位小数、盈利带 `+`；负数用 `-` 前缀而非括号。

## §6 出图实现要点

海报不是截屏，是把那块 DOM 现场转成 PNG。由此产生四条硬约束，换实现时必须保留：

1. **海报组件内全部用内联样式**，不能依赖外部样式表——转图时外部样式可能不参与计算。
2. **不引任何网络字体**。转图时字体不嵌入，网络字体会在导出图里退化成别的字体，出现"预览好看、存下来变样"。数字用系统自带等宽字体。
3. **图片素材必须与站点同源**。背景插画放在站内资源目录；跨域图片可能在转图时取不到，导致导出的是一张缺图的海报。头像目前是第三方外链，属已知风险（见 §8）。
4. **出图在弹窗打开后延迟一小段时间触发**，等 DOM 稳定。出图期间预览上盖一层加载圈，Save 置灰。

导出参数：2 倍像素比、底色 `#0a0c14`、跳过字体嵌入、绕过图片缓存。

## §8 已知缺口（研发实施时必须处理）

按严重程度排序。这些不是需求变更，是当前实现的欠账。

1. **邀请码可能印错（高）**。海报上的邀请码来自异步查询，而出图不等它返回。查询没回来时海报会印出兜底占位码，用户以为分享出去了自己的码，实际拉新归因会丢。修法：把"档案与邀请码都已就位"作为出图的前置条件传给弹窗——结算详情那条链路已经这么做了，Lite 这条漏了，照抄即可。
2. **域名三套并存且写死在代码里（高）**。分享链接、二维码、以及其他海报里的站点地址分别写着三个不同域名，其中一个并非本项目在用的域名，链接大概率打不开；同一张海报上的分享链接与二维码甚至指向不同域名。修法：收敛成一个由环境变量提供的站点地址常量，全部引用它。**上线前必须处理，否则分享出去的每一张图都指向错地址。**
3. **窄屏可能裁切（中）**。海报固定 400px 宽，弹窗里预留了缩放变量但从没有人给它赋值，因此在更窄的手机上海报会溢出被裁。修法：按容器宽度算缩放比并写入该变量。
4. **头像走第三方外链（中）**。用户头像目前指向外部头像生成服务。该服务不可用或跨域取图失败时，导出的海报头像位会是空白。修法：头像落到自己的存储，或在出图前把头像转成内联数据。
5. **有一个没人用的旧分享卡组件（低）**。仓库里存在一个已无任何引用的结算分享卡组件，实施时不要照它写，直接跳过。
6. **排行榜有另一套同名弹窗（低）**。排行榜页面自带一个同名但独立实现的分享弹窗，与本文描述的这套没有关系，不要混用。
7. **分享行为没有任何记录（低）**。目前分享、保存、复制链接都不产生任何埋点或服务端记录，无法统计分享量与回流。要做增长归因的话这是前置项。

## §9 不在本特性范围内

以下三条与分享相关但**不属于本文覆盖范围**，各自独立实现，不要一起改：

| 功能 | 在哪 | 说明 |
|---|---|---|
